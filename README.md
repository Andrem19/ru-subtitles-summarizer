# RU Subtitles & Study Guide

[![Release](https://img.shields.io/github/v/release/Andrem19/ru-subtitles-summarizer?label=release)](https://github.com/Andrem19/ru-subtitles-summarizer/releases/latest)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

Расширение для **Chromium-браузеров** (Chrome, Edge, Brave, Opera, Vivaldi, Arc), которое автоматически переводит английские субтитры видео на **русский язык** прямо в плеере, а по кнопке **📚** собирает учебный конспект лекции. Работает с плеерами **Kaltura**, встроенными **видео YouTube** и обычными **HTML5-плеерами** — на любом сайте, а не только на одном университетском портале.

Переводчик подключается вами: подойдёт любой **OpenAI- или Anthropic-совместимый API** — облачный (Z.ai, OpenAI, OpenRouter, DeepSeek, Groq…) или локальный (Ollama, LM Studio), с вашим собственным ключом.

> Открываешь лекцию → запускаешь видео → появляются русские субтитры; кнопка 📚 — конспект.

---

## What it does (Что делает)

- Автоматически обнаруживает caption playlist (`.m3u8` с `.vtt`-сегментами или прямой `.vtt`) через `chrome.webRequest` — никакого DevTools.
- Скачивает **все** сегменты субтитр сразу и разбирает их в единый список фраз.
- **Оригинальные тайминги сохраняются без изменений** — ИИ переводит только текст, синхронизация не съезжает.
- Отправляет текст в переводчик **батчами по 40 фраз** (соседние фразы дают контекст), модель видит `{"id","text"}` и никогда не видит тайминги.
- Строгая валидация ответа: потерянные/перенумерованные id → повтор, затем автоделение батча пополам. Один сбой не ломает транскрипт.
- **Кэш переводов в IndexedDB** (ключ = hash(язык+модель+текст), не signed URL) — повторное открытие лекции показывает субтитры мгновенно, без повторного перевода.
- Приоритетная очередь: сначала переводятся фразы рядом с текущей позицией видео, остальное — фоном.
- Два видео на одной странице (например, Part A & B) переводятся независимо: у каждого свой чип со своим прогрессом.
- Плавающий чип **RU** на плеере: клик — режимы `Русские → Рус+EN → Выкл`, правый клик — меню (режимы, «Повторить перевод», «Настройки»). Чип и кнопка **📚** стоят одним рядом у правого края плеера на середине высоты — вне нижней панели управления, где у плееров (Kaltura и YouTube) расположены свои кнопки, включая полноэкранный режим.
- Наши элементы рисуются в отдельном слое поверх плеера (не внутри его DOM): иначе собственные слои плеера перекрывают кнопки — они выглядят нормально, но клики достаются плееру.
- Кнопка **📚 Конспект** на плеере: генерирует по полной транскрипции учебный конспект — краткая сводка, ключевые моменты, подробный разбор по темам с таймкодами и глоссарий терминов EN↔RU; модель добавляет пояснения «💡 Пояснение:» от себя. Конспект кэшируется (открывается мгновенно), есть кнопка «↻ Заново».
- Понятные ошибки: «API-ключ не задан», «неверный API-ключ (401)», «сервер недоступен», тост с кнопкой «Повторить».
- **Видео с YouTube**, встроенные в страницы, работают так же: тот же чип RU, те же русские субтитры поверх плеера, та же кнопка 📚 с конспектом (см. раздел *YouTube*).

## How it works (Как устроено)

```
плеер запрашивает субтитры → .m3u8/.vtt запрос → webRequest ловит URL
  → фоновый service worker скачивает плейлист + все сегменты
  → парсит WebVTT (тайминги сохраняются) → нормализует (дедуп границ сегментов)
  → шлёт cues в content script того фрейма, где плеер
  → движок перевода: уникальные фразы → батчи → выбранный вами API
  → кэш IndexedDB → переводы возвращаются в content script
  → субтитры показываются в плеере (overlay), синхронно с видео
```

## Требования

- Chromium-браузер версии **110+**: Chrome, Microsoft Edge, Brave, Opera, Vivaldi, Arc (любая ОС — Windows, macOS, Linux).
- Node.js 18+ — **только если собираете из исходников**. Готовую сборку можно скачать и поставить без Node.
- Ключ провайдера перевода **или** локальная модель (ключ не нужен).

Firefox не поддерживается: расширение построено на MV3-варианте `chrome.webRequest`, который в Firefox работает иначе. Для Firefox нужен отдельный манифест — в планах нет.

## Installation (Установка)

### Вариант 1: готовый ZIP (Node не нужен)

1. Откройте [последний релиз](https://github.com/Andrem19/ru-subtitles-summarizer/releases/latest) и скачайте `ru-subtitles-study-guide-vX.Y.Z.zip`.
2. Распакуйте архив в постоянную папку (например, `Documents\ru-subtitles`) — из неё расширение и будет работать.
3. Откройте страницу расширений браузера и включите **Developer mode** (режим разработчика):

   | Браузер | Адрес |
   |---|---|
   | Chrome | `chrome://extensions` |
   | Edge | `edge://extensions` |
   | Brave | `brave://extensions` |
   | Opera | `opera://extensions` |
   | Vivaldi | `vivaldi://extensions` |

4. **Load unpacked** (Загрузить распакованное) → выберите папку, куда распаковали архив (в ней должен лежать `manifest.json`).
5. Откройте настройки расширения (кнопка **RU Subtitles & Study Guide** на панели или правый клик по чипу → «Настройки») и вставьте свой API-ключ.

### Вариант 2: из исходников

1. Скачайте репозиторий (или `git clone`).
2. Соберите расширение:
   ```
   cd extension
   npm install
   npm run build      # → extension/dist/
   ```
3. Дальше — те же шаги 3–5, только выбирать папку `extension/dist`.

### Обновление

- Из ZIP: скачайте новый архив, распакуйте поверх старой папки, затем нажмите **Reload** (⟳) у расширения.
- Из исходников: `git pull` → `npm run build` → **Reload** (⟳).

Историю изменений смотрите в [CHANGELOG.md](CHANGELOG.md); как участвовать в разработке — в [CONTRIBUTING.md](CONTRIBUTING.md).

## Настройка переводчика (провайдер и ключ)

Страница настроек: страница расширений → **RU Subtitles & Study Guide** → **Extension options**, либо правый клик по чипу RU → «Настройки».

Выберите провайдера в списке — endpoint, модель и ссылка «Где взять ключ» подставятся автоматически:

| Пресет | Endpoint | Ключ |
|---|---|---|
| **Z.ai · GLM-5.3 Flash (Coding Plan)** — по умолчанию | `https://api.z.ai/api/anthropic` | ключ Coding Plan с [z.ai/subscribe](https://z.ai/subscribe) |
| **OpenAI** | `https://api.openai.com/v1` | ключ `sk-…` с [platform.openai.com/api-keys](https://platform.openai.com/api-keys) |
| **OpenRouter** | `https://openrouter.ai/api/v1` | ключ `sk-or-…` с [openrouter.ai/keys](https://openrouter.ai/keys) |
| **DeepSeek** | `https://api.deepseek.com/v1` | ключ с [platform.deepseek.com/api_keys](https://platform.deepseek.com/api_keys) |
| **Groq** | `https://api.groq.com/openai/v1` | ключ `gsk_…` с [console.groq.com/keys](https://console.groq.com/keys) |
| **Ollama (локально)** | `http://127.0.0.1:11434/v1` | **не нужен** — данные не покидают компьютер |
| **LM Studio (локально)** | `http://127.0.0.1:1234/v1` | **не нужен** |
| Другой OpenAI-совместимый | ваш URL | если ваш сервер его требует |

Порядок действий:

1. Выберите пресет (или впишите свой endpoint вручную).
2. Вставьте свой API-ключ в поле **API-ключ** (ссылка «Где взять ключ» ведёт на страницу ключей провайдера).
3. Проверьте модель (кнопка **Список моделей** подставит доступные) и при желании измените **целевой язык** (по умолчанию `Russian`).
4. **Сохранить** → **Проверить подключение** — кнопка делает живой тест-перевод одной фразы и показывает ответ модели.

Если ключ не задан, страница настроек сразу показывает предупреждение, а плеер при первой же попытке перевода пишет: «API-ключ не задан для …» — вместо невнятного «сервер недоступен».

Про локальные модели: запустите `ollama serve` и заранее скачайте модель (`ollama pull llama3.1`) либо включите локальный сервер в LM Studio (`lms server start`). Ключ для них не требуется, и текст субтитр вообще не уходит в интернет.

## Settings (Настройки)

- Провайдер / Endpoint / API-ключ / Модель / Целевой язык (по умолчанию `Russian`)
- Режим по умолчанию: **Русские** или **Русский + English** (bilingual)
- Способ отображения: **Overlay** (по умолчанию — работает в плеере Kaltura mwEmbed и в fullscreen) или **TextTrack** (нативный рендер браузера; работает на обычных HTML5-плеерах, но mwEmbed Kaltura его не отображает)
- Автоперевод на любом сайте, где найден плеер (включён по умолчанию)
- Размер шрифта субтитров и размер шрифта конспекта
- Фраз в батче (40), Temperature (0.2), Параллельных запросов (2)
- Очистить кэш переводов (+ счётчик), Проверить подключение

## Использование

1. Откройте страницу с видео (лекция на портале, YouTube-вставка, любой HTML5-плеер).
2. На каждом плеере появится чип: `RU off` → клик (или сам включится в авто-режиме) → `RU 12%…87%` → зелёный `RU`.
3. Запускайте видео — русские субтитры появляются синхронно. Seek, пауза, скорость — работают автоматически (overlay следует за `currentTime`).
4. Правый клик по чипу: режим «Русский + English» покажет оригинал и перевод вместе; там же «Повторить перевод» и «Настройки».
5. Кнопка **📚** на плеере — учебный конспект лекции: краткая сводка, ключевые моменты, разбор по темам с таймкодами (можно найти нужный момент в видео) и глоссарий терминов формата «**English term** — русский перевод: определение». Модель добавляет собственные учебные пояснения (💡), чтобы материал понимался без видео. Первый раз конспект готовится ~30–90 сек, дальше открывается мгновенно из кэша; «↻ Заново» пересоздаёт его.
6. Повторное открытие лекции: субтитры и конспект сразу (всё из кэша), фон догоняет остальное.

## YouTube (встроенные видео)

Видео с YouTube (`https://www.youtube.com/embed/VIDEO_ID`) расширение обрабатывает тем же способом, что и Kaltura:

```
content script в iframe плеера → videoId → фон
  A) прямой запрос watch-страницы + timedtext  → YouTube часто отдаёт 0 байт
                                                 (нужен proof-of-origin токен)
  B) плеер сам включает CC → webRequest ловит его запрос /api/timedtext
        → скачиваем таймтекст по этому URL → разбор (JSON3 или XML)
  → cues в iframe → перевод + overlay + чип RU + 📚 конспект (как в Kaltura)
```

Что важно знать:

- Английская дорожка субтитров выбирается автоматически (сначала обычная, потом авто-сгенерированная).
- Расширение **не меняет** ваши настройки субтитров YouTube: если CC были выключены, оно на секунду включает их, чтобы плеер запросил таймтекст, и возвращает как было. Если CC уже включены — ничего не трогает.
- Тайминги берутся из YouTube (`tStartMs` / `dDurationMs`) — в точности как в оригинале.
- Субтитры подгружаются автоматически при старте страницы и повторно — при нажатии Play (плеер запрашивает таймтекст только у «живого» медиаэлемента). Если плеер ещё не готов, попытки повторяются каждые 8 секунд.
- Если видео ещё не воспроизводилось, автозагрузка может не сработать сразу — просто нажмите Play, и субтитры подтянутся.
- Конспект кэшируется по `yt:VIDEO_ID`, поэтому при повторном открытии страницы он открывается мгновенно.

## Troubleshooting (Проблемы)

| Симптом | Причина / решение |
|---|---|
| «API-ключ не задан для …» | Откройте настройки и вставьте ключ провайдера. Локальным моделям (Ollama, LM Studio) ключ не нужен. |
| Чипа нет | На странице нет плеера с субтитрами (или у видео вообще нет субтитров). Расширение работает на любом сайте, но переводить ему нечего, пока плеер не запросил caption-поток — запустите видео. |
| `RU !` / красный тост «Не удалось подключиться…» | Endpoint недоступен (нет интернета, локальный сервер не запущен, неверный URL). Нажмите «Повторить». |
| «Ошибка авторизации (401)» | Неверный или отозванный API-ключ — обновите его в настройках. |
| «Лимит запросов провайдера…» | Слишком много запросов подряд (бесплатные тарифы). Подождите около минуты; помогает уменьшить «Параллельных запросов» до 1–2. |
| Модель отвечает мусором / конспект не в формате | Возьмите модель посильнее (например, GPT-4o-mini, GLM-5.3 Flash, DeepSeek) — совсем маленькие локальные модели хуже держат формат. |
| Субтитры отстают от видео | Первый просмотр: перевод догоняет в фоне (прогресс на чипе). Второй просмотр — мгновенно. Увеличьте «Параллельных запросов» до 3–4. |
| Английские субтитры Kaltura дублируются | mwEmbed рисует свои caption своим DOM — программно отключить безопасно нельзя. Просто не включайте штатный CC — расширение показывает русский отдельно. |
| TextTrack выбран, но субтитров не видно | Это ограничение mwEmbed Kaltura. Переключите «Способ отображения» на **Overlay**. |
| На YouTube чип не появился | Видео ни разу не воспроизводилось: плеер запрашивает субтитры только у активного медиаэлемента. Нажмите Play — субтитры подтянутся (и при следующем открытии страницы тоже). |

## Privacy и разрешения (Приватность)

- **Никакой телеметрии, аналитики и «домашних» серверов.** Расширение не общается ни с чем, кроме указанного вами endpoint перевода.
- **Что и куда уходит:** только английский текст субтитр (и он же — в запрос конспекта). Тайминги, название видео, URL и данные страницы на endpoint не отправляются. Если выбрать локальную модель (Ollama, LM Studio), наружу не уходит вообще ничего.
- **API-ключ** хранится только в локальном хранилище браузера (`chrome.storage.local` этого профиля), не синхронизируется между устройствами, не пишется в файлы и не попадает в страницы: доступ к нему есть только у service worker расширения. В репозитории ключа нет и никогда не было.
- **Кэш переводов и конспектов** — локальный IndexedDB; очищается кнопкой в настройках.
- **Почему расширение просит доступ ко всем сайтам** (`<all_urls>`): субтитры могут лежать на любом домене — портал вуза, CDN, YouTube, и плеер может быть в iframe. Чтобы находить caption-поток и рисовать чип где угодно, расширению нужно видеть запросы `.m3u8`/`.vtt` и работать в кадрах страницы. Ничего, кроме субтитр, оно не читает и никуда не отправляет.
- Пароли, cookies и токены сессий не собираются.

## Architecture (Архитектура)

```
extension/
  manifest.json          MV3, host-permissions: <all_urls> (субтитры бывают на любом CDN)
  src/
    shared/              чистая логика (тестируется в Node):
      hls.ts             парсер m3u8 (мастер/медиа/субтитры), resolve URL
      vtt.ts             парсер WebVTT + нормализация (дедуп границ сегментов)
      timedtext.ts       парсер таймтекста YouTube (JSON3 и legacy XML)
      batching.ts        батчи по числу фраз/символам, split
      translate.ts       промпт + строгий парсер ответа (id-валидация)
      protocol.ts        клиент: OpenAI-compatible и Anthropic-compatible
      settings.ts        дефолты, пресеты провайдеров, ключи-хинты, merge (с миграциями),
                         missingKeyMessage (понятная ошибка вместо «сервер недоступен»)
                         и toUiSettings — настройки без API-ключа для страниц
      studyguide.ts      чанкинг транскрипции, промпты конспекта, валидация ответа
      markdown.ts        безопасный рендер markdown (только DOM-узлы, без innerHTML)
      diag.ts            диагностический ring-buffer → chrome.storage.local
      hash.ts            sha256-ключи кэша, entryId из URL Kaltura
    background/
      detection.ts       webRequest-детекция (.m3u8/.vtt + content-type), claim-механизм
      pipeline.ts        probe playlist → download segments → cues
      youtube.ts         watch-страница → captionTracks → timedtext (+ разбор)
      engine.ts          очередь батчей, приоритет по currentTime, ретраи/сплиты
      guides.ts          генерация конспекта (map-reduce), кэш по entryId, ретраи 429
      llmQueue.ts        глобальный шлюз запросов (лимит параллельных + минимальный интервал)
      cache.ts           IndexedDB (translations + guides)
      index.ts           SW: маршрутизация сообщений, доставка в кадры, перехват timedtext
    content/
      index.ts           привязка cues↔<video>, чип, overlay, ветка YouTube-iframe
      assoc.ts           выбор видео (duration matching) — чистая функция
      tracks.ts          TextTrack + подавление нативных EN-треков (best effort)
      overlay.ts         fallback-отрисовка субтитр в контейнере плеера
      studyPanel.ts      панель конспекта (копирование, перегенерация, размер шрифта)
      ui.ts              чип RU / кнопка 📚 / меню / тосты
    options/             страница настроек (выбор провайдера, ключ, тест подключения)
  tests/                 68 тестов: hls, vtt, timedtext, batching, translate, hash, assoc,
                         pipeline (HTTP), engine, studyguide, markdown, settings
  dist/                  собранное расширение (load unpacked)
```

Собирается esbuild'ом: `npm run build` (watch: `npm run watch`). Тесты: `npm test` (`node --test`, 68/68 ✓). Типы: `npm run typecheck`. Всё вместе — `npm run gate` (см. «Проверка перед публикацией»).

### Диагностика без DevTools

Обе половины расширения пишут короткий ring-buffer в `chrome.storage.local` (ключи `diagBG` и `diagCS`): старт YouTube-ветки, результат прямого пути, перехваченный timedtext, доставка cues, геометрия слоя с кнопками. Прочитать их можно прямо с диска, пока браузер открыт:

```
node tools/read-diag.mjs \
  "$LOCALAPPDATA/BraveSoftware/Brave-Browser/User Data/Default/Local Extension Settings/<ID расширения>" \
  diagCS diagBG
```

ID расширения виден на странице `brave://extensions` (у распакованной сборки он зависит от пути к папке).

## Проверка перед публикацией (локально)

GitHub Actions **не участвует** в проверке этого проекта. Hosted-запусков нет,
статус-чека, которого нужно дождаться, тоже нет, и платный billing для проверки
не нужен. Проверка — это локальные команды ниже, выполненные на машине
разработчика на том же коммите, который идёт в PR. Результат (команда, ОС, версия
Node, SHA коммита) указывайте в самом PR: незапущенную проверку нельзя выдавать за
пройденную.

```bash
cd extension
npm ci          # ровно то, что записано в package-lock.json
npm run gate    # typecheck → тесты → сборка → проверка исходников, dist/ и манифеста
```

`npm run gate` — вся последовательность одной командой. Отдельные шаги:

| Команда | Что проверяет |
|---|---|
| `npm run typecheck` | `tsc --noEmit`, без ошибок |
| `npm test` | 68 тестов (`node --test`), офлайн, без браузера |
| `npm run build` | сборка `dist/` |
| `npm run verify` | в отслеживаемых файлах нет ключей и доменов конкретного вуза; в собранном `dist/` их тоже нет; `dist/manifest.json` — MV3 с `<all_urls>` |

`npm run verify` проверяет **и исходники, и собранный бандл** — устаревший `dist/`,
собранный до правки, это отдельная ошибка, а не тихий пропуск. Скрипт запускается
локально, без сети и без сторонних зависимостей.

Чего эти команды **не** делают: они не открывают браузер. Живая проверка (чип,
субтитры, конспект) остаётся ручной — см. `testpage/` ниже и список в
[CONTRIBUTING.md](CONTRIBUTING.md).
