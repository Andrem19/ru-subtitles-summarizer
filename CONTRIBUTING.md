# Как помочь проекту

Спасибо за интерес! Ниже — как поднять проект локально, что проверяется перед
приёмом изменений и куда смотреть в коде.

## Разработка

```bash
cd extension
npm ci             # ровно то, что записано в package-lock.json
npm run watch      # пересборка при изменениях (или npm run build — один раз)
npm test           # тесты, node --test
npm run typecheck  # tsc --noEmit
npm run gate       # всё перед PR: typecheck → тесты → сборка → проверка исходников и dist
```

Установка в браузер: страница расширений (`chrome://extensions`,
`brave://extensions`, `edge://extensions`…) → **Developer mode** →
**Load unpacked** → папка `extension/dist`. После пересборки нажмите **Reload** (⟳)
у расширения и обновите страницу с видео — content-скрипты живут в старой копии
до перезагрузки вкладки.

Локальный стенд для отладки детекции и перевода (имитирует трафик Kaltura):

```bash
cd testpage && python -m http.server 8899
# http://127.0.0.1:8899
```

## Что проверяется перед приёмом изменений

GitHub Actions в проекте не используется: проверка идёт локально, на вашей машине,
на том же коммите, который вы отправляете в PR. Приложите к PR результат — команду,
ОС, версию Node и SHA коммита. Незапущенная проверка не считается пройденной.

Одной командой: `npm run gate`. По шагам:

1. `npm run typecheck` — без ошибок.
2. `npm test` — все тесты зелёные (68). Новую логику в `src/shared/` добавляйте
   вместе с тестами: эти модули чистые и запускаются в Node без браузера.
3. `npm run build` — сборка проходит.
4. `npm run verify` — в отслеживаемых файлах нет ключей и доменов конкретного вуза,
   в собранном `dist/` их тоже нет, манифест — MV3 с `<all_urls>`. Проверяйте
   **после** сборки: устаревший `dist/` — это ошибка, а не пропуск.
5. Изменения проверены вживую хотя бы на `testpage/` (чип, субтитры, конспект).
   Ни одна из команд выше браузер не открывает.
6. Никаких ключей, токенов и личных данных в коммите. API-ключ живёт только в
   `chrome.storage.local` браузера и вводится пользователем на странице настроек —
   в репозитории его быть не должно никогда. Пункт 4 проверяет это автоматически,
   но только для строк, похожих на ключ: глазами всё равно смотрите.

## Как устроен код

- `src/shared/` — чистая логика: парсеры HLS/WebVTT/таймтекста, батчинг,
  протоколы API, настройки, промпты конспекта, markdown, хэши, диагностика.
  Здесь приветствуются тесты и отсутствие зависимостей от `chrome.*`.
- `src/background/` — service worker: детекция потоков через `webRequest`,
  скачивание сегментов, движок перевода, генерация конспекта, кэш в IndexedDB.
- `src/content/` — то, что видит пользователь в плеере: чип «RU», слой интерфейса,
  overlay субтитров, панель конспекта.
- `src/options/` — страница настроек.

Полезные детали: интерфейс всегда монтируется в отдельный слой поверх плеера
(`.rusub-layer`), потому что собственные слои плееров перекрывают всё, что
положено в их DOM; переводы и конспекты кэшируются по хэшу содержимого, поэтому
подписанные ссылки на плейлисты можно менять свободно. Диагностика без DevTools —
`tools/read-diag.mjs` (см. README).

## Пул-реквесты

- Один PR — одна тема; опишите, что проверяли вживую.
- Стиль кода — как в соседних файлах: комментарии по делу, без «шума».
- Пожалуйста, не добавляйте зависимостей без необходимости: расширение собирается
  одним esbuild без рантайм-библиотек.
